# SMART CYBER UNIVERSITY — 통합 플랫폼 v3 (개발·시연용)

기존 v2 디자인(대학 포털, LMS, 학사행정, AI 튜터, 네이비/앰버, KO/EN/ZH/VI, 시니어 모드)을 유지하며 **정규화된 학사 데이터베이스** 및 **별도 출석정책 검증 화면**을 추가했습니다.

## 실행

Python 3.10+ 환경에서 `python server.py` 실행 → `http://127.0.0.1:8765` 접속. **반드시 서버로 실행**해야 v3 기능이 동작합니다. 환경변수 `PORT`(기본 8765), `SCU_DB`(기본 `campus_demo.sqlite3`)를 설정할 수 있습니다. 외부 서비스 설치는 필요 없습니다.

| 역할 | ID | 시연 전용 비밀번호 |
|---|---|---|
| 학생 | `student` | `student123!` |
| 교수자 | `professor` | `professor123!` |
| 관리자 | `admin` | `admin123!` |

1. 학생 로그인 후 `나의 스마트캠퍼스` 하단의 **학사 DB 연계 체험 v3** 패널로 이동합니다.
2. **DB 수강신청**: 초깃값 3개 강좌(9학점)가 등록되어 있으므로 한 과목 취소 후 다른 강좌 신청을 시험합니다.
3. **영상 출석 정책 검증**: 과목·차시를 고르고 **시연 영상 재생**을 클릭해 15초간 정상 시청합니다. 12초 이상 재생시간을 인정받고 종료 시 DB에 기록됩니다. 재생위치만 바로 끝으로 이동하면 인정되지 않습니다.
4. **학적 신청 접수**: 신청 사유 입력 시 `pending` 상태로 DB에 저장됩니다. 실제 학적 변경/결재는 발생하지 않습니다.
5. 교수자/관리자로 로그인하면 포털의 **v3 · 학습·감사 기록** 버튼으로 역할별 서버 집계를 확인할 수 있습니다.

## 데이터베이스

`academic.py`에서 테이블을 생성합니다.

| 테이블 | 용도 |
|---|---|
| `academic_courses` | 과목코드·강좌명·학점·담당교수 |
| `enrollments` | 학생별 신청 강좌, 최대 9학점 |
| `video_sessions` | 학생·강좌·차시별 영상 재생 세션 및 누적 인정초 |
| `attendance` | 데모 출석정책을 만족한 최종 기록 |
| `academic_requests` | 휴학·복학·전공변경 신청(대기 상태) |
| `academic_audit` | 학적 신청·수강신청·출석 이벤트 감사 기록 |

기존 `student_state`는 과거 UI에서 사용하는 **비공식 로컬 진행 상태**입니다. 이 값은 `attendance`와 연결되지 않으며 출석 인정에 사용하지 않습니다. 두 진도 표시는 서로 다를 수 있습니다. 운영 전에는 기존 UI 표시를 통합 API에 맞춰 전환해야 합니다.

## 주요 API

- `GET /api/v3/catalog`: 과목 및 신청 현황
- `POST /api/v3/enrollment`: `{course, operation: "enroll"|"drop"}`
- `POST /api/v3/video/start`: `{course, lesson}` → session_id
- `POST /api/v3/video/progress`: `{session_id, position, ended}` → 재생 인정시간 및 상태
- `GET /api/v3/attendance`: 본인 데모 출석 기록
- `POST /api/v3/requests`: `{type: "leave"|"return"|"major_change", note}`
- `GET /api/v3/overview`: 교수자 본인 담당 과목/관리자 전체 시연 출석, 관리자 감사 로그

기존 `/api/login`, `/api/logout`, `/api/tutor`, `/api/state` 등 v2 API 유지.

## 자동 검사

`python -m unittest -v test_v3` — 로그인/접근제어, 학점 상한, 미수강 강좌 차단, 탐색으로 건너뛰기 시 출석 불인정, 정상 누적 인정, 감사 로그 등 **5개 API 통합 테스트**.

## 주의: 운영 환경 사용 불가

- 공개된 테스트 계정과 메모리 세션, 로컬 SQLite, 비밀번호 초기화·잠금 정책 부재 등으로 실서비스 배포 금지.
- 시청시간은 클라이언트가 보고하며 서버가 시간경과와 위치변화의 상한만 확인합니다. 배속·중단·브라우저 조작·다중세션·접속 장애·인증 교체 등을 제어하는 **공인 출석 검증이 아닙니다.** 임의로 강의 인정을 확정해서는 안 됩니다.
- 요청은 시연용 `pending`에 저장되며 승인 워크플로·자격 요건·학칙 심사는 구현되지 않았습니다.
- 공식 운영을 위해서는 DB 서버(PostgreSQL 등), 애플리케이션 서버/마이그레이션, 계정관리·MFA·HTTPS·Secure 쿠키·CSRF 전면 방어·레이트리밋·권한별 세부 검증·감사로그 보호·백업 복구·동영상 CDN/DRM·학습분석·학사 ERP API 및 접근성 검수 필요.
- AI 튜터는 기존 로컬 교안 검색 방식으로 남아 있습니다. `OPENAI_API_KEY`를 제공한 경우에만 외부 모델 요약을 시도합니다. 개인정보 또는 공식 학사처리 질문에는 사용하지 마세요.
- 개발 서버는 127.0.0.1에만 바인딩. 공개 인터넷 배포 구조가 아닙니다.
